# Contributing to Xerness

Thanks for your interest in Xerness. This repository is the **public home and reference documentation** for Xerness, part of the [XAgent](https://xagt.ai) family. Contributions of all sizes are welcome — from fixing a typo to proposing a new workflow pattern.

## Ways to contribute

- **Report a problem or request a feature** — open an [issue](https://github.com/xerpa-ai/xerness-intro/issues). Please search existing issues first.
- **Improve the documentation** — clarity, accuracy, examples, and diagrams in the README, `ARCHITECTURE.md`, `USE-CASES.md`, or `FAQ.md`.
- **Share a workflow or skill pattern** — propose a reusable role, workflow DAG, or skill template via an issue or pull request.
- **Ask a question** — use [Discussions](https://github.com/xerpa-ai/xerness-intro/discussions) or an issue.

## Pull request process

1. **Fork** the repository and create a branch from `main`:
   ```bash
   git checkout -b docs/clarify-quickstart
   ```
2. **Make focused changes.** One logical change per pull request keeps review fast.
3. **Keep the tone and style consistent** — concise, professional, English. Match the existing voice.
4. **Verify links and formatting** render correctly on GitHub.
5. **Open a pull request** with a clear title and a short description of *what* changed and *why*.

## Style guidelines

- **Language:** English only.
- **Voice:** direct and factual. Prefer showing (examples, diagrams) over telling.
- **Formatting:** Markdown, GitHub-flavored. Wrap code in fenced blocks with a language tag.
- **Diagrams:** SVG assets live in `assets/`; keep them on the brand palette (ink `#0A0A0A`, paper `#FFFFFF`, grey `#8b8b8b`, green `#63E6A2`).
- **No secrets, ever.** Do not include API keys, credentials, internal URLs, or private data in any contribution. See [SECURITY.md](./SECURITY.md).
